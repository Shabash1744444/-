# C4 G331 C001 — исправление истории диалога в исходном организме

**8 октября 2026** · экспериментальный checkpoint, не canonical и не готовая AGI/свободная русская речь.

## Что было сломано

G331 принимала `REPORT` и видела конфликт двух сообщений, но не умела отличить конфликт от явного пересмотра собственного сообщения источником. Прямой `CORRECT` отвергался. После первоначального локального ремонта выяснилось, что компактный `.c4m` при обычной загрузке исключал устаревшую SOURCE-запись в cold-only сегмент; поэтому исторический запрос возвращал UNKNOWN. Ещё важнее: обученный G329 `.c4m` использует для `COLOR` значение типа `entity`, а пустой граф — `literal`; статический строковый код работал на пустой базе, но не на настоящих весах.

## Что сделано в существующем c4child

- `c4child/structured_cognition.py`: добавлен типизированный `CORRECT` с обязательной ссылкой `replaces` на конкретное предыдущее пользовательское событие. Совпадение source, контекста (scope/scene/frames), субъекта, предиката, object-kind; старое SOURCE-утверждение помечается `SOURCE_SUPERSEDED`, новое связывается через `correction_of`, статус истины мира не повышается.
- `QUERY as_of_turn`: проверка **времени получения в диалоге** (external_order), а не заявленного времени события или UTC. Возвращает историческую позицию источника из того же **C4Graph**; неизвестные времена не домысливаются.
- `REPORT/QUERY/CORRECT` теперь уважает фактический `object_mode` из обученного `.c4m` (`literal` или `entity`). Это существенно для реального G329 `COLOR`.
- `c4child/checkpoint.py`: `SOURCE_SUPERSEDED` остаётся в hot-графе на обычной загрузке компактного `.c4m`, без отдельной базы истории и без канонизации WORLD.

## Ограничение времени

`as_of_turn` — это **номер входящей реплики с момента текущего реального диалога** по `external_seq`; он не равен часам, дате мира или внутреннему циклу. Полные три времени и обобщение естественных языковых времён пока НЕ реализованы.

## Как испытать через существующее Android-приложение

1. Сначала остановить C4 и сохранить отдельную **резервную копию своего `.c4m`**.
2. В C4 Nursery: **Система → Импорт runtime ZIP** → `C4_G331_C001_NATIVE_RUNTIME.zip`.
3. Открыть **прежний `.c4m`** (не создавать и не импортировать новую модель), включить TRACE.
4. Отправить одним сообщением (чтобы слова `prism`/`mint` не были заученным answer-key):

```text
@c4 {"op":"REPORT","scope":"STORY","scene":"c001","fact":{"subject":"prism","relation":"COLOR","object":"mint"}}
```

5. Найти во входном событии TRACE/логах `in:...` — идентификатор именно первого `REPORT`. Использовать его в `replaces`:

```text
@c4 {"op":"CORRECT","scope":"STORY","scene":"c001","replaces":"in:ID_ИЗ_ЛОГА","fact":{"subject":"prism","relation":"COLOR","object":"ochre"}}
@c4 {"op":"QUERY","scope":"STORY","scene":"c001","fact":{"subject":"prism","relation":"COLOR","object":"?"}}
@c4 {"op":"QUERY","scope":"STORY","scene":"c001","fact":{"subject":"prism","relation":"COLOR","object":"?"},"as_of_turn":1}
```

`as_of_turn:1` корректен для **чистой** истории с первой входящей репликой `REPORT`; если уже были реплики, укажи её фактический `external_order` из лога. Ожидается `ochre` для текущего запроса и `mint` для исторического. После checkpoint, stop/restart должно остаться то же.

6. Экспортировать чат+сырую трассу, не только скриншоты. Физический Android для C001 пока **НЕ проверен**.

Полноценное понимание русского языка, весь проект C4, человекоподобный диалог, независимо подтверждённый Android outcome/reward, обучение причинно-композиционным операциям, многошаговое планирование и непрерывное временное рассуждение **не реализованы/не подтверждены этим ремонтом**.
