# C4 — причины решений, данные, контрпримеры, неопределённость
Дата: 2026-10-08. Статус: инженерный журнал ВНЕ скрытого рассуждения модели.
Этот документ фиксирует проверяемые наблюдения и публично объяснимые основания. НИ ОДИН пункт не равен обещанию, что новый C4 уже работает.

## I. Явные авторские ограничения

- C4 и Singularity OS — два разных проекта. Никакого смешения.
- Исходные 4 owner: EVAL, COMMIT, DRIVE, MEDIATE, **без добавления нового конституционного owner**.
- Пять влияний: MASK, VALUE, AVAIL, TRIGGER, STATUS. 4×4×5=80 coarse signatures, **не 80 жёстких функций или смысловых ребёр**.
- Авторский критерий интеллекта «Интелект это способность решать нестандартные задачи не стандартными методами.» сохранён в `C4_FIFTH_LAW_INTELLIGENCE_NON_CONSTITUTIONAL_2026-10-08.md`; это цель испытаний, не 5-й owner.
- Цель автора: органическая непрерывная модель присутствия; кто я/ты/он/она в каждом nested frame; говорящий, слышащий, свидетель, участник; два вида времени + реальное внешнее время; ирония/постирония; повторное рефлексивное рассуждение, даже без внешней реплики; инициатива/спонтанные темы.
- Не хардкодить правильные ответы и не делать из C4 справочник / LLM wrapper. Учить переносу способностей.
- До активного предобучения доказать работоспособность механики; после обучения искать ошибки труднее.

## II. Что действительно подтверждено

**A. Нормативные документы**: `FOUR_LAWS_CONSTITUTION.md`, `TRAINING_LAWS.md`, `C4_FOUR_LAWS_MATHEMATICAL_SKELETON_V01_2026-10-08.md`. Они определяют законы, но **не доказывают реализацию в каждом вызове**.

**B. Аудит по G222–G310**: `FOUR_LAWS_TRAINING_AUDIT_G222_G310_2026-10-08.md`.
- Несколько путей мутации: `EpistemicAdmissionOrgan`, `BootstrapTeacher`, `C4ChildDialogue`.
- `BootstrapTeacher` / `C4ChildDialogue` могли вызывать прямой commit/replace, обходя эпистемический путь.
- `graph.truth()` на историческом состоянии мог принимать активное учительское SOURCE утверждение за универсальную истину.
- Исторические queue/wait/pending-ask механизмы обладали незаслуженной властью над DRIVE.
- В более поздней линии G314–G323 часть этих нарушений отдельно исправлялась; НЕ объявлять, что старый аудит всё ещё однозначно описывает все файлы новых веток без сравнения веток.

**C. G323-P9**: `00_READ_ME_FIRST.md` и `01_NEXT_CHAT_HANDOFF.md` указывают на успешный эксперимент вложенной перспективы и самопроверки, **не canonical** и не доказательство свободного русского диалога. Не терять его при работе с веткой G329.

**D. G329 Android REAL**: `experimental_g330/G329_REAL_DEVICE_CAUSAL_AUDIT.md` и выгрузки `c4_chat_1791469053232.json` / `c4_chat_1791470574930.json`.
- Наблюдаемый ответ `Не за что` ⇒ `По текущей теме у меня доступно: буква Ю — гласная буква.`. Ошибка привязки темы/выбора speech act, но точная доля ошибок EVAL vs context consumer требует узкого повторного трассирования.
- Сложный 14/7/4 batch ⇒ `EVAL_SOURCE_EPISODES`, `COMMIT_NOOP`, `DRIVE EVIDENCE_BOUNDED_RECALL`; 13 повторных blanket fallbacks вместо локальной сцены.
- Система перепутала USER экзаменационный вопрос `Какие вопросы ты сама задавала?` с фактом собственных C4 ASK. Это violation source-role.
- `answer_batch` принципиально не обрабатывает обычный локальный смысловой вопрос: для не-memory-query используется шаблон отказа. Это **кодовый потолок**, не недостаток весов.
- `.c4m` (2,065,628 байт; SHA `dfe4b40211b1ce2d3400e95217ecc9210fc1f0a93076ee42a51e55f0be0b090f`) содержит накопленный структурный граф, приблизительно 10,727 entities / 10,781 facts; это НЕ эквивалентная 2 MB полноценная языковая LLM.
- На устройстве чистый G329 организм не импортировался: `DIGEST_COLLISION_SIZE_MISMATCH`; при этом G329-style runtime trace существует. Значит runtime и organism — разные доказательства загрузки.
- Экспорт transport trace выдаёт `TRACE_TOO_LARGE` (51.2+ MB и позднее 88.5+ MB); нельзя считать его полным по отсутствующим событиям. Чат `eventId` пустой из-за `event_id`/camelCase несовместимости.

**E. G330 RED**: `experimental_g330/RED_TEST_G329.log`: 3 теста упали; 2 на локальной сцене (камень / стакан), 1 на C4 ASK vs USER question. RED не есть реализованная G330.

## III. Логические выводы (гипотезы, НЕ готовые факты о полном исправлении)

1. Интеллект не возникает из соблюдения конституции автоматически: нужен **обучаемый универсальный механизм построения структур/гипотез/методов**, который способен действовать на новых задачах.
2. Граф знаний — носитель данных, не самостоятельный семантический reasoner. Добавлять корпус до архитектурного исправления опасно.
3. Сквозная сцена `who did what to whom where when, according to whom` должна быть структурой с собственными truth scopes, а не набором ключевых слов.
4. Один закон COMMIT обязан иметь **одну точку принудительного enforcement** для признанного состояния, а не только одноимённые классы в нескольких модулях.
5. Полный **all-mechanism contract** можно спроектировать заранее, но нельзя заранее подтвердить все learning algorithms и unlimited generalization.
6. Полный reboot тоже рискован: G323 и G314–G322 содержат настоящие инженерные находки. Лучше новый независимый integration spine, старые органы как проверяемые плагины, старые веса и истории read-only для миграции.

## IV. Исключённые ложные «успехи»

- Текстовый blueprint != Python runtime.
- 700+ PASS != пройденный live разговор.
- UNKNOWN на все вопросы != понимание.
- Прямая цитата из старого user prompt != собственная память C4.
- EVAL сказал UNKNOWN, DRIVE сказал ANSWER != доказательство обоснованности ответа.
- `CASCADE_OUTCOME` с пустыми added IDs при изменении order != полноценная delta-инструментация.
- Подбор заранее известных имён/фраз в тесте != перенос на новые сущности.
- Копия знания, пересказ и собственный прежний ответ != новые независимые доказательства.
- Модель может автономно кодить != модель способна самостоятельно доказать достаточность архитектуры.
- Новая ветка/новый номер G330 != новый рабочий орган и не canonical.
