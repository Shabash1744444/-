# 2. WHAT G303 AND G304 FIXED

## G303 — EVENT TENSE BOUNDARIES

Real counterexample 1:
negative past event could be stored with EVENT_POLARITY=NEG, but the language query for that negative past event was rejected before reaching episodic memory.

Repair:
negative past event truth queries now reach event memory.

Real counterexample 2:
`Антон будет любить чай`
could create a garbage subject:
`Антон будет`
and then store a current LIKES relation.

Repair:
bounded Russian periphrastic future is recognized:
`буду / будешь / будет / будем / будете / будут + infinitive`

Laws:
- PAST EPISODE != CURRENT STATE
- FUTURE CLAIM != CURRENT STATE
- FUTURE CLAIM != PAST EPISODE
- FUTURE CLAIM != VERIFIED OUTCOME
- TENSE AUXILIARY != SUBJECT IDENTITY
- EVENT QUERY != NEW EVIDENCE

Future statements may be represented as future event claims but do not become verified world state.

## G304 — EVENT CONJUNCTION SCOPE

Counterexample:
`Антон любил чай и сок`
was stored as one object literal `чай и сок`, so querying `Антон любил чай?` could remain UNKNOWN.

Safe repair:
for a positive SET-valued event predicate, a conjunction may produce separately queryable proposition-events.

However:

`Антон не любил чай и сок`

must NOT automatically become:
- Антон не любил чай
- Антон не любил сок

because negation scope is ambiguous.

Laws:
- POSITIVE SET CONJUNCTION MAY DISTRIBUTE
- NEGATED CONJUNCTION != DISTRIBUTED NEGATION
- KNOWN MULTIWORD ENTITY > SURFACE SPLIT
